# RPG 화면·한 판 통과 테스트 (2026-11-01 / 로컬 0.6.57)

## 사용 방법

기존 로컬 서버 `http://127.0.0.1:58179/` → 싱글플레이 → RPG 모드 → **테스트 모드**.

- **프롤로그·화면 테스트**: 현재 68초 프롤로그 뒤 **주점이 이미 열린 지도**를 보여 준다. 테스트 표시 아래 **화면 바로가기**에서 주점·지도·프롤로그 다시 보기·ST1/2/3 전투 화면을 자유롭게 선택한다. 주점이나 다른 스테이지 화면을 보기 위해 싸울 필요가 없다. 화면을 선택할 때마다 새 임시 상태를 구성하므로 앞선 화면에서 한 구매·전투 진행은 이어지지 않는다. 실제 전투 화면을 선택하면 기존 전투 조작은 가능하지만 다른 화면으로 바로 옮겨도 된다.
- **한 판 통과 테스트**: 같은 프롤로그와 화면에서 시작한다. 스테이지 승부 한 판이 끝나면 승패·남은 적 HP·내 HP 0 여부와 무관하게 통과 처리하고 보상은 주화로 자동 선택하여 다음 지도를 연다. ST1 뒤 주점, ST2 뒤 갈림길을 방문할 수 있고 ST3에서 현재 개발 구간을 완료한다. 지도에서 다음 승부를 선택하는 기존 흐름은 유지한다. 독립된 주점 3판 승부의 판수는 바꾸지 않는다.

상단에 TEST 표시와 **테스트 종료** 버튼을 제공한다. 두 모드는 메모리 안의 임시 여정이고 테스트 진행은 저장·전적·영구 해금에 반영하지 않는다. 종료·새로고침하면 테스트 진행은 사라진다. 기존 RPG 및 예전 5판 랜덤 장비 테스트 저장은 보존한다. 실제 RPG를 열어 둔 상태에서 시작하면 기존 나가기 루틴으로 실제 여정을 먼저 저장하며, 실패하면 테스트를 시작하지 않는다.

## 후속 수정 · 전투 없는 화면 확인

사용자가 주점 확인을 위해 또 싸워야 하는 불편을 알려 주어 화면 테스트에 직접 이동을 추가했다. 변경은 `lib/rpg-preview.ts`, `app/components/RpgPreviewTools.tsx`, `app/components/RpgJourney.tsx`, `app/page.tsx`, `app/rpg-journey.css`, `tests/rpg-preview.test.tsx`와 이 기록/루트 README다. 일반 RPG의 잠금 조건이나 기존 한 판 통과 테스트는 바꾸지 않았다.

- 이번 후속 검증: 테스트 모드 **7개**, 프롤로그 **5개**, 기존 여정 **1개 파일**로 합계 **13개 통과**. 주점/지도/ST1~3 자유 이동에 실제 패 행동이 필요하지 않음, 초기 객체 미변경, 다른 여정과 한 판 모드의 직접 이동 차단, 주점이 열린 시작 지도, 메뉴 렌더를 확인했다.
- TypeScript와 신규 테스트 관련 코드 ESLint 통과. 아래 최초 작업 검증 기록과 이번 실행 범위는 구분한다.
- 실제 브라우저 클릭·모바일 배치는 여전히 미검증이며, 기존 브라우저 사용 제한을 우회하지 않았다. 빌드·배포·새 저장 키 추가는 하지 않았다.

## 이번 검증

- 신규 **5개 통과**: 메뉴/종료 표시 정적 렌더, 일반 화면 모드의 기존 규칙 유지·다른 여정/장비 테스트 격리, 패배 1판씩 ST1→2→3·주점·갈림길 연결/중복 보상 방지, HP 0 후 통과·장비 복구/기존 저장 바이트 보존, 정상 클리어 중복 정산 방지/주점 미니게임 규칙 보존.
- 프롤로그 기존 **5개** 및 `rpg-journey`, `rpg-phase-one`, `rpg-stage-ui` **3개 파일** 통과. 이번 합계 **13개 통과**, 실행한 검사 실패 0. 전체 테스트를 실행한 것은 아니다.
- 최종 TypeScript 검사 통과. 신규 모듈·컴포넌트·테스트 ESLint 오류 0. 새 CSS 구문 확인 및 `git diff --check` 통과.
- 추가로 `RpgJourney.tsx` 전체 린트를 실행했을 때 기존 `RpgResult`의 조건부 useState 오류 4개·경고 10개가 나온다. HEAD 원본을 ESLint 표준입력으로 별도 검사하여 동일한 오류 4개(`react-hooks/rules-of-hooks`)·경고 10개를 확인했다. 이번 신규 코드 린트 통과와 구분하며 기존 결과 컴포넌트는 이 작업에서 재설계하지 않았다.
- 기존 서버의 `/`, `/app/components/RpgPreviewTools.tsx`, `/lib/rpg-preview.ts` 응답을 새로 확인: 모두 HTTP 200.
- 개발 서버 실행 요청은 이미 실행 중인 서버(PID 20076, 포트 58179)가 있음을 반환하여 기존 서버를 보존하고 응답 확인에 사용했다. 서버를 종료·교체하지 않았다.
- **실제 메뉴 클릭·모바일/PC 화면·터치·청감은 미검증**. 브라우저 열기 도구가 이번에도 `Local browser use is disabled in Work settings`를 반환했다. HTTP/정적 렌더 통과는 실제 화면 검증을 의미하지 않는다.

빌드·커밋·push·원격 저장·배포는 하지 않았다. 프롤로그 최종 미술 교체와 정식 엔딩 이후 2회차 연결의 선행조건은 [이전 보고서](rpg-prologue-local.md)에 기록한 상태를 유지한다.
